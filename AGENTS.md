# Agent Guidelines for Extraction Shooter

This document provides essential information for agentic coding agents working in the `ExtractionShooter` repository.

## 1. Project Overview
- **Type:** Minecraft Mod (NeoForge)
- **Concept:** "Tarkov-like" extraction shooter experience in Minecraft.
- **Language:** Kotlin (JVM 21)
- **Mod Loader:** NeoForge (Targeting Minecraft 1.21.11)
- **Mappings:** Parchment (2025.12.20)
- **Key Libraries:** GeckoLib (Animations/Models), Kotlin for Forge.

## 2. Build & Execution Commands
Always use the Gradle wrapper (`./gradlew`).

- **Verify Compilation:** `./gradlew classes` (Quickly check for syntax/compile errors).
- **Build Project:** `./gradlew build` (Full build; note that this may run existing tests).
- **Run Client:** `./gradlew runClient` (Launches Minecraft client with mod).
- **Run Server:** `./gradlew runServer` (Launches dedicated server).
- **Clean Build:** `./gradlew clean`
- **Data Generation:** `./gradlew runData` (Generates JSON assets/data from code).

## 3. Code Style & Conventions

### General Philosophy
- **No New Tests:** Do not implement new unit tests or GameTests unless explicitly requested.
- **Compilation First:** Use `./gradlew classes` as the primary verification step after making changes.

### Kotlin Idioms
- Use **data classes** for simple state/data holders (e.g., `PlayerHealth`).
- Prefer **expression bodies** for simple functions: `fun isDead() = health <= 0`.
- Use **`when` expressions** for exhaustive branching over enums/sealed classes.
- Leverage **null safety** strictly; avoid `!!` unless absolutely certain.
- Use **trailing commas** in multi-line parameter lists and collection literals.
- Prefer **`val`** over `var` whenever possible to ensure immutability.

### Naming Conventions
- **Classes/Objects:** `PascalCase` (e.g., `ModItems`, `GridInventoryMenu`).
- **Variables/Properties:** `camelCase` (e.g., `playerInventory`, `headHealth`).
- **Constants:** `SCREAMING_SNAKE_CASE` (e.g., `const val ID = "extractionshooter"`).
- **Packages:** `lowercase.dot.separated` (e.g., `com.gmail.vincent031525.extractionshooter`).
- **Registry Objects:** Often named exactly matching their registry key (e.g., `val M4A1 = ITEMS.register("m4a1") { ... }`).

### Imports
- Prefer explicit imports for project-specific classes.
- Star imports (`*`) are acceptable for:
    - Registry classes (e.g., `com.gmail.vincent031525.extractionshooter.registry.*`)
    - Mojang/Minecraft math or utility classes if heavily used.
- Organize imports: Standard libraries first, then Minecraft/NeoForge, then project-specific.

### Registration Pattern
- Use `DeferredRegister` for all registry entries (Items, Blocks, Menus, etc.).
- Group registrations in `com.gmail.vincent031525.extractionshooter.registry`.
- Initialize registries in the `init` block of the main mod class `Extractionshooter` using `MOD_BUS`.
- Common Registries:
    - `ModItems`: All item definitions.
    - `ModBlocks`: All block definitions.
    - `ModMenus`: GUI/Menu container types.
    - `ModDataAttachments`: Custom player/entity data.
    - `ModEffects`: Custom status effects.

## 4. Project Structure
- `src/main/kotlin`: All Kotlin source code.
- `src/main/resources`: Static assets (textures, sounds) and `META-INF/neoforge.mods.toml`.
- `src/generated`: Resources generated by `./gradlew runData`. **Do NOT edit these manually.**
- `src/main/templates`: Templates for metadata expansion (e.g., `neoforge.mods.toml`).
- `conductor/`: Contains project management docs (tech-stack.md, product.md, etc.).
- `models/`: Source models (e.g., `.bbmodel` files).

## 5. Error Handling & Logging
- **Logging:** Use `Extractionshooter.LOGGER` (Log4j 2).
- **Levels:** 
    - `INFO`: General initialization/status.
    - `DEBUG`: Verbose debugging information (e.g., packet received).
    - `ERROR`: Unexpected failures or crashes.
- **Exceptions:** Catch specific exceptions. Avoid empty `catch` blocks. 
- Use `LOGGER.error("Context message", exception)` to preserve stack traces.

## 6. Minecraft/NeoForge Best Practices
- **Side Safety:** Use `runForDist` or check `EffectiveSide` when performing side-specific logic. Client-only code (renderers, GUI) must be properly isolated.
- **Network:** Use the NeoForge network system for custom packets.
- **Codecs:** Use Mojang `Codec` (and `RecordCodecBuilder`) for data serialization (NBT/JSON).
- **Events:** Use `@SubscribeEvent` on methods. Ensure you are subscribing to the correct bus:
    - `MOD_BUS`: Used for initialization events like `FMLCommonSetupEvent`, `EntityRenderersEvent.RegisterRenderers`, and Registry events.
    - `GAME_BUS`: Used for gameplay events like `LivingHurtEvent`, `PlayerEvent.ItemPickupEvent`, etc.

## 7. Development Workflow
- **DataGen First:** When adding items/blocks, add them to the registry and then create/update the corresponding DataGen provider (e.g., `ModItemModelProvider`) before running `./gradlew runData`.
- **Git Commit Style:**
    - `feat: ...` for new features.
    - `fix: ...` for bug fixes.
    - `refactor: ...` for code cleanup.
    - `docs: ...` for documentation changes.
- Ensure `./gradlew classes` (or `./gradlew build`) passes before submitting changes.

## 8. Specialized Rules
- **GeckoLib:** When working with GeckoLib models, ensure the animation controller names match the JSON files in `src/main/resources/assets/extractionshooter/animations/`.
- **No Cursor/Copilot Rules:** No specific `.cursorrules` or `.github/copilot-instructions.md` files were found. Follow the general guidelines in `conductor/code_styleguides/general.md`.
